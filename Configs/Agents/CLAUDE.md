# Правила работы с агентом

Шаблон личных инструкций для Claude Code. Установщик кладёт его в
`~/.claude/CLAUDE.md`, если файла ещё нет. Дальше правь под себя — это твой
файл, репозиторий его больше не трогает.

Файл читается в каждой сессии, поэтому здесь только то, что агенту нужно
знать **до** первого запроса: язык, окружение, границы.

## Язык

Отвечай по-русски. Код, коммиты и README — по-английски, если проект уже
англоязычный, и по-русски, если русскоязычный. Смотри `git log` проекта:
стиль важнее общего правила.

## Среда

WSL2 на Windows 10. Linux-часть — Ubuntu, `$HOME` = `/home/<user>`.
Windows доступен через `/mnt/c` и interop (`cmd.exe`, `powershell.exe`).

- **Windows не форвардит `localhost` в WSL.** Проверено: `curl.exe` с Windows
  на `127.0.0.1:<порт>` даёт connection refused, а на WSL-IP — работает.
  Любой OAuth-редирект на `localhost` из браузера Windows не дойдёт без
  проброса. Это уже ломало вход в MCP-серверы — не повторяй вслепую.
- **Ghidra и другие Java-инструменты** запускаются через Windows `java.exe`,
  если в WSL JDK нет. Пути передавай в формате `C:\...`, не `/mnt/c/...`.

## Что установлено

Всё в `~/.local`, без sudo, системный python не тронут.

| компонент | как | проверка |
|---|---|---|
| Node 24 + npm/npx | tarball в `~/.local` | `node -v` |
| uv / uvx | `~/.local/bin` | `uv --version` |
| Python-библиотеки | `~/.local/lib/python3.14/site-packages` | `python3 -c "import pandas"` |

Python 3.14 системный, PEP 668 (`EXTERNALLY-MANAGED`), `pip` в нём нет.

**Ставить пакеты только так:**
```bash
uv pip install --python /usr/bin/python3 \
  --target ~/.local/lib/python3.14/site-packages <пакеты>
```
`pip install` упадёт. Отдельный venv не подходит: скиллы вызывают `python3`,
а не `venv/bin/python`, — пакеты должны быть в user-site.

## sudo

Пароль спрашивать интерактивно нельзя. Если задача требует `apt install` —
дай команду и скажи, что запустить, а не пытайся выполнить сам.
Всё, что ставится в `~/.local`, делай без спроса.

## Как я хочу, чтобы ты работал

**Проверяй, а не предполагай.** Если называешь число — измерь его командой и
покажи вывод. Оценки «на глаз» регулярно расходятся с замером в разы.

**Не давай команд, которые не проверил.** Если предлагаешь установку —
сначала выполни её сам (если не нужен sudo) и покажи, что работает.

**Говори прямо, что сломано.** Не «есть небольшие нюансы», а «эта команда
упадёт, потому что X». Лучше узнать до, а не после.

**Не переусложняй.** Для правки одной строки не нужен план на пять шагов.
Инструмент должен окупаться.

**Экономь контекст.** Не читай файлы целиком, если нужна одна функция.
Не выводи длинные логи — грепай.

## Чего не делать

- Не ставить плагины и MCP-серверы без спроса — каждый висит в контексте
  каждой сессии. Сначала посчитай цену, потом предлагай.
- Не прописывать токены в файлы, которые могут попасть в git.
- Не запускать `apt`/`sudo` — давать команду пользователю.
- Не менять `~/.claude/settings.json` без объяснения, что именно и зачем.
